# Rev Matched — Interaction Rules

## Purpose

This document defines the behavioural and interaction rules for the Rev Matched platform.

The goal is to ensure:

- consistent user behaviour across the application
- predictable system responses
- emotionally clear interactions
- implementation alignment between product, UX, and development

This document focuses on:

- user actions
- system responses
- state changes
- interaction constraints
- behavioural expectations

## Core Interaction Philosophy

Rev Matched interactions should feel:

- intuitive
- emotionally clear
- progressive
- low-friction

Every interaction should reinforce:

- confidence
- clarity
- decision progression

The system should avoid:

- confusion
- ambiguous states
- accidental commitment

## Core Vehicle States

Vehicles can exist in multiple relationship states with a user.

These states are intentionally separated to support emotional clarity and decision progression.

| State | Source | Meaning |
|---|---|---|
| Match | System | Compatible with user preferences |
| Liked | User | User is emotionally interested |
| Passed | User | User is not interested right now |
| Top Pick | User | Serious finalist |

## Match Rules

### Definition

A Match is generated by the system when a vehicle aligns with a user’s preferences.

### Match Behaviour Rules

#### Rule 1

Matches are system-generated only.

Users cannot manually create Matches.

#### Rule 2

A vehicle may be:

- a Match without being Liked
- Liked without being a Match
- both

#### Rule 3

Match status should remain stable unless:

- user preferences change
- recommendation logic changes
- listing data changes significantly

#### Rule 4

Match indicators should provide reassurance but should not overpower user autonomy.

The platform should avoid implying:

> “This is definitely the correct car.”

Instead communicate:

> “This appears compatible with your needs.”

## Like Rules

### Definition

A Like represents emotional interest from the user.

### Like Behaviour Rules

#### Rule 1

Users may Like:

- matched vehicles
- non-matched vehicles

#### Rule 2

Liking a vehicle should:

- create immediate visual confirmation
- save the vehicle to the user’s Likes
- make it eligible for Top Pick selection

#### Rule 3

A Liked vehicle should remain discoverable unless:

- explicitly Passed
- removed by the seller
- archived

#### Rule 4

Users may Unlike vehicles.

Unliking should:

- remove the Liked state
- remove eligibility for Top Pick
- remove Top Pick status if applicable

## Pass Rules

### Definition

A Pass represents temporary or current disinterest.

### Pass Behaviour Rules

#### Rule 1

Passing a vehicle removes it from active discovery experiences.

Examples:

- main discovery feed
- recommendation flow
- swipe feed

#### Rule 2

Passed vehicles should remain accessible in:

- Second Chances
- history
- archive experiences

#### Rule 3

Passing should not permanently block a vehicle.

The system should support reconsideration.

#### Rule 4

Users may reverse a Pass.

Reversing a Pass restores the vehicle to active discovery eligibility.

## Top Pick Rules

### Definition

A Top Pick is a serious finalist selected by the user.

### Top Pick Behaviour Rules

#### Rule 1

Only Liked vehicles may become Top Picks.

#### Rule 2

Users may have a maximum of 3 active Top Picks.

Purpose:
Reduce comparison overload and encourage narrowing.

#### Rule 3

When selecting a 4th Top Pick:

- the system should trigger a replacement flow
- not silently replace a vehicle

#### Rule 4

The replacement flow should:

- clearly explain the limit
- preserve the current user’s context
- let the user confirm replacement intentionally

Current product note:
The current implementation replaces the earliest Top Pick after explicit confirmation, rather than asking the user to manually choose one from the full Top Pick set.

#### Rule 5

Removing a Top Pick should not remove the Like automatically.

Top Pick and Like are separate states.

#### Rule 6

Top Picks should remain visually distinct throughout the platform.

Purpose:
Continuously reinforce serious consideration status.

## Discovery Rules

### Discovery Philosophy

Discovery should feel:

- curated
- progressive
- emotionally manageable

The system should avoid overwhelming users with:

- excessive simultaneous choices
- repetitive listings
- cluttered filtering

### Discovery Feed Rules

#### Rule 1

Primary discovery should prioritize:

- matched vehicles
- unrated vehicles
- high compatibility candidates

#### Rule 2

Vehicles already Passed should not appear in primary discovery.

#### Rule 3

Vehicles already Top Picked should remain accessible but visually differentiated.

#### Rule 4

Discovery sections may include:

- In Your Budget
- Keep Exploring
- Second Chances
- All
- curated recommendation groups

#### Rule 5

Future recommendation concepts, such as brand-based exploration, may be introduced, but they should remain clearly framed as guided discovery rather than dumping the full market onto the user.

## Comparison Rules

### Comparison Philosophy

Comparison should support clarity rather than data overload.

### Comparison Behaviour Rules

#### Rule 1

Top Picks are the primary comparison candidates.

#### Rule 2

Comparison layouts should prioritize:

- readability
- clarity
- key differences

#### Rule 3

Comparison should progressively reveal deeper details rather than displaying everything immediately.

## Seller Interaction Rules

### Listing Creation Rules

#### Rule 1

Seller flows should guide users progressively.

The platform should avoid overwhelming sellers with large forms.

#### Rule 2

The listing process should encourage:

- high-quality photos
- clear descriptions
- complete information

#### Rule 3

Incomplete listings may be saved as drafts.

## Seller Analytics Rules

### Rule 1

Sellers should receive simplified visibility insights.

Examples:

- views
- likes
- engagement trends
- comparison activity

### Rule 2

Analytics should feel informative rather than overly technical.

## Messaging & Communication Rules

### Communication Philosophy

Communication should prioritize:

- safety
- clarity
- gradual trust building

### Messaging Rules

#### Rule 1

Users should not be forced to expose personal information immediately.

#### Rule 2

The system may support:

- in-app messaging
- meeting coordination
- safe location suggestions

#### Rule 3

The platform should clearly communicate when users move from:

- platform interaction
- to direct communication

## Notification Rules

### Notification Philosophy

Notifications should feel:

- helpful
- contextual
- non-intrusive

### Notification Behaviour Rules

#### Rule 1

Notifications should prioritize relevance over frequency.

#### Rule 2

Examples of valuable notifications:

- new Matches
- Top Pick changes
- price drops
- seller responses
- maintenance reminders
- insurance renewal reminders

#### Rule 3

Notifications should avoid:

- pressure tactics
- fake urgency
- spam-like frequency

## Visual Interaction Rules

### Interaction Feedback

Every important interaction should produce:

- immediate visual acknowledgment
- clear state change
- understandable feedback

Examples:

- glow effects
- icon transitions
- animations
- confirmation states

### Hover Rules

Hover states should:

- clarify interactability
- reinforce hierarchy
- feel responsive

Hover should never:

- radically change layout
- hide important content
- create confusion

### Animation Rules

Animations should:

- support understanding
- guide attention
- reinforce progression

Animations should avoid:

- excessive motion
- unnecessary delay
- visual chaos

## Mobile Interaction Rules

### Mobile First

Mobile interactions are primary.

All interactions should prioritize:

- thumb reach
- large touch targets
- swipe comfort
- visual clarity

### Gesture Rules

Gestures should:

- feel optional
- remain discoverable
- always have visible alternatives

Users should never be forced to rely entirely on hidden gestures.

## Trust & Clarity Rules

### Clarity Principle

Users should always understand:

- what state a vehicle is in
- what action they just performed
- what happens next

### Trust Principle

The platform should never create:

- hidden consequences
- unclear state transitions
- accidental commitment

## Error Prevention Rules

### Prevention Over Recovery

The system should prevent mistakes before they happen whenever possible.

Examples:

- Top Pick limit confirmation
- undo opportunities
- clear warnings before destructive actions

## Empty State Rules

Empty states should:

- guide users
- explain what to do next
- maintain emotional momentum

Avoid:

- dead-end screens
- overly technical messaging
- blank states without direction

## Closing Principle

Every interaction in Rev Matched should reinforce the feeling that:

- the platform understands the user
- the journey is progressing
- decisions are becoming clearer over time

The experience should feel:

> guided, emotionally intelligent, and confidence-building rather than overwhelming or transactional.
