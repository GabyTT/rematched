# Docs Index

This folder contains the working product, UX, tone, terminology, and data-model reference docs for RevMatched.

## How To Use This Folder

These docs are doing two different jobs:

- **Strategy docs** describe the intended product direction, experience philosophy, and design logic.
- **Current-state reference docs** describe how the product currently behaves, how key concepts are being modeled, and what real-world inventory constraints we already know about.

If you are new to the project, it helps to know which kind of document you are reading.

## Suggested Usage

Use these docs to keep product thinking, interface language, and data-model decisions aligned.

Recommended flow:

1. Read `product-vision.md` for the overall product purpose.
2. Read `user-journey-map.md` to understand the full lifecycle journey.
3. Read `screen-descriptions.md` to understand how that journey appears in the current product.
4. Read `matching-logic-notes.md` and `interaction-rules.md` for how the buyer flow and recommendation system currently behave versus where they are heading.
5. Read `implementation-gap-notes.md` when deciding what product areas most need deeper implementation work.
6. Read `build-roadmap.md` when sequencing that work into practical product phases.
7. Use `ux-principles.md`, `revmatched-tone.md`, and `terminology.md` when shaping interface behaviour, naming, and copy.
8. Use `rev-matched-data-dictionary.md`, `real-listing-field-analysis.md`, `listing-ingestion-product-notes.md`, `listing-ingestion-implementation-brief.md`, and `admin-ingestion-workflow.md` when discussing listing structure, normalization, ingestion, admin review workflow, and future schema work.
